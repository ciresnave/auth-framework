# Reviewed field names for the derive(Debug) audit (tests/code_quality_audit.rs,
# test_derived_debug_plain_fields_are_reviewed).
#
# Every struct / enum in src/ that derives Debug and has a plain-text field (String, Vec<u8>,
# Vec<String>, Option of those, Box<str>, Arc<str>) is checked by FIELD NAME:
#   public          the name is fine anywhere: identifiers, URLs, names, protocol metadata, public keys and
#                   certificates, timestamps, diagnostic text, single-use protocol values that travel in the
#                   clear (state, nonce, jti, ...). Personal data (email, phone_number, username, ip_address)
#                   is listed here too: this audit covers credentials, not privacy.
#   secret_capable  the name can hold a credential or a bearer value. A derived Debug is a FAILURE unless the
#                   type has a hand-written redacting Debug (preferred) or an [allow] line below.
#   ambiguous       free-form content (a body, a query, a url that may embed a password, ...): same rule.
#   container_ok    the name of a map, set or JSON value (HashMap<String, _>, HashSet<String>, serde_json::Value, ...) that
#                   holds attributes, claims, labels, configuration objects or other non-credential data and is keyed by
#                   no credential. A container's Debug prints every key and value, so a map keyed by a token or session
#                   id, or holding request parameters, a response body or a settings bag that can carry a secret, is NOT
#                   listed here: redact it (hand-written Debug) or [allow] it with a reason.
#   allow           path:Type:field | one-line reason it is public information. `<tuple>` is a tuple
#                   struct / tuple variant payload.
# A field name on no list FAILS: adding a field with a new name needs a decision here.
# Zeroizing<String>, HashMap values and other wrapper types are not plain text and are not scanned.
