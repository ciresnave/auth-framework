**Breaking: the access-control cache no longer serves a decision past its grant's expiry.** `CachedAuthorizer` could reuse an Allow for up to 60 s after the grant behind it (or an ancestor in its delegation chain) had expired, because the cache entry stored no expiry. `access_control::Answer` gains a `valid_until: Option<DateTime<Utc>>` (the earliest expiry of any grant that took part, `None` when nothing expires), the engine fills it in, and the cache reuses an entry only while `now` is before it. A custom `Source` that builds an `Answer` must set `valid_until` (use `None` if it cannot tell, which keeps today's behaviour for it). Tests in `tests/access_control_cache_tests.rs`: an allow cached at t is denied at the grant's expiry inside the 60 s window (fails on main), and the same through a delegation chain.
