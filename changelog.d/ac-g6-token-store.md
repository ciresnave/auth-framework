GNAP token storage (G6 slice 2): `GnapService` keeps issued access tokens through the new `GnapTokenStore` trait (`protocols::gnap_store`; `InMemoryTokenStore` is the default, `GnapService::with_token_store` swaps it), so a deployer can keep them in a database or a shared cache and a token survives a restart when the store does. `GnapIssuedToken` is now public. A store error refuses the request it happens in and is never read as "no such token"; if the store cannot keep a new token, none is returned and its consent record is withdrawn. Additive: with no store set, behaviour is unchanged. Transactions are still held in memory (a later G6 slice). Four service tests and four store tests, two mutation checks (read error treated as no token; consent kept after a failed insert) each fail the matching test.
