GNAP key rotation (RFC 9635 6.1.1): a token bound under `jws` or `jwsd` can be re-bound to a new key by a POST to its manage URI that both keys prove (`GnapService::rotate_token_key_with_proof`, `gnap_jws::verify_attached_rotation` and `verify_detached_rotation`); refusals answer `invalid_rotation` or `key_rotation_not_supported`, other tokens cannot rotate their key, and discovery now reports `key_rotation_supported: true`. A service message that starts with a registered GNAP error code and a colon is answered with that code (`GnapError::from_service_message`, `GnapError::http_status`). A transaction that receives five wrong interaction hashes or references (`GnapService::with_max_bad_attempts`, `0` turns it off) is deleted and the fifth is refused with `too_many_attempts` (429); `GnapTransaction` gains a `bad_attempts` field, so code that builds one by struct literal must add it.
 The JavaScript SDK dev dependencies move to `@typescript-eslint` 8.74 and `rimraf` 6.1 so no copy of `minimatch` below 11.0.1 that the alert covers remains in its lockfile (Dependabot #154, GHSA-g3hv-75wg-m249).GNAP redirect and app start modes (RFC 9635 3.3.1, 3.3.2): `GnapService::redirect_callback` builds the callback URI for an approved transaction, and `GnapService::with_app_uri` offers the `app` start mode with the transaction id as its `txn` parameter.
GNAP `interact.hints` (RFC 9635 2.5.3): `ui_locales` is validated when a transaction opens and readable through `GnapService::interaction_locales`; `GnapInteractionRequirements` gains a `hints` field, so code that builds one by struct literal must add it.
