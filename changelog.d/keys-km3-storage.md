**`keys::KeyStore`: key storage by capability (ROADMAP KM3).** A `KeyStore` declares what it can do (`StoreCapabilities`: exportable, signs in place, persistent) and signs through itself, so a store that never releases a private key fits the same trait. `MemoryKeyStore` and `FileKeyStore` ship: the file store keeps one AES-256-GCM record per key (sealed with the existing `StorageEncryption` / `KeyProvider`, bound to the key id, written through a temp file and rename), fails the open on a record it cannot decrypt, and erases the private half on `Destroyed`. Only an `Active` key signs; `publish_jwks` lists active and retiring keys, never pending, revoked or destroyed ones. No new dependency; an OS keystore or TPM store is a later, separate step. Nothing existing calls it yet.
