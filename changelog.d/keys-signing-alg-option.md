**Breaking: `LocalKey::signing_alg()` returns `Option<SigningAlg>`.** It returned a `SigningAlg`, which has no honest answer for a key that does not sign, and the X25519 key-agreement keys designed in `docs/KEY_AGREEMENT_DESIGN.md` (KM2) will be such keys. Every key a `LocalKey` can be today signs, so the call returns `Some(alg)` and the only change is the type: write `key.signing_alg().expect("a signing key")` or match on the `Option` (callers that compared with a `SigningAlg` compare with `Some(alg)`). Nothing else in the crate called it. Evidence: a new `keys::generate` test (ES256, ES384, EdDSA, RS256 each report `Some(alg)` and sign with it), written before the change and shown failing to compile against the old signature, and the one existing caller updated.
