**Admin: `security reindex` and `security encrypt-tokens` finish the token and session sealing arc (ADR-011, slice 4 of 4).** `reindex` re-seals every sealed token and session under the current storage key, so the old key can be removed after a rotation; records it cannot open are reported and left untouched, and the command fails so the old key is not dropped early. `encrypt-tokens` seals every token and session still stored as a plaintext typed row (SQLite, PostgreSQL and Redis are enumerated; the in-memory store has nothing to sweep), writing the sealed copy before deleting the plaintext row, and reports how many plaintext rows remain. `--dry-run` only counts; `--purge-legacy --confirm` deletes the plaintext rows instead of sealing them, which forces every holder to log in again. Expired rows are deleted, not sealed. `auth-storage-sqlite` is built by the embedding application, so the CLI cannot reach it.
