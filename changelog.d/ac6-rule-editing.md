**`access_control` rule editing, ancestor revocation and audit trail (ROADMAP AC6).** `InMemoryEngine::add_rule` and `remove_rule` let an actor edit rules about an object if it is the account holder, a strict owner-ancestor of the principal the object names (`agent:<id>@...`), or holds the engine's edit action (`with_edit_action`) over an object that contains it; a deny on the edit action blocks that object and every pattern over it, and an inactive actor edits nothing. The issuer of a rule or share can remove it, and removal cascades to everything shared from it. Rules added by an editor are root rules issued by the editor. `audit_log` records every add, removal, share and refusal with the actor and the rule's source chain. `Grant` gains an `issuer` field. A refused delegation, a duplicate rule id and an empty rule id (`RuleError::InvalidId`) are now recorded in the audit trail as `Refused`, as the module doc says; a pattern edit is blocked only by an edit-action deny that could overlap the pattern, not by any deny the actor has; `add_rule` bumps the engine generation so the cache sees a new rule at once.
