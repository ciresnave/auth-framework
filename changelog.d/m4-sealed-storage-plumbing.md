**Breaking (custom storage backends): `AuthStorage` gains `lists_kv_keys()` (default `false`) and `EncryptedStorage::try_new`, groundwork for sealing tokens and sessions at rest (ADR-011, slice 1 of 4).** Nothing is sealed yet and no stored data changes. `StorageEncryption` now derives one blind-index key per encryption key id (an HMAC of the data key, kept after the raw key is zeroized), reachable as `blind_index`/`blind_index_current` (and `key_ids` lists the keys to probe), so a later slice can name records by a keyed index instead of a raw bearer value. A backend that lists its KV keys should override `lists_kv_keys` to return `true` (every in-tree backend does); `try_new` refuses a backend that does not, or that does not report KV TTLs, and `EncryptedStorage::new` is unchanged.
