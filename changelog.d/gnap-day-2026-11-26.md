Cancelling a GNAP grant request (DELETE on the continuation URI, RFC 9635 5.4) now also revokes the access tokens issued under that grant.

The object form of GNAP `interact.start` (`{"mode":"redirect"}`, RFC 9635 2.5.1) now reads on the wire; an object with no string `mode` is refused when the request is read. A retried token rotation is not answered with a token already past its lifetime, and a token that carries no key leaves no retry record (RFC 9635 11.33). Gap-doc notes: 11.20 narrowed to the responses that carry token material, 11.33 retry is per process, 11.30 is structural.

The `iss` of a GNAP `iss_sub` subject identifier is now the authorization server identifier (RFC 9635 3.4): `GnapService::with_issuer`, else the interaction base URL; with neither, `iss_sub` is not offered. It was the literal `self`.

The GNAP continuation `uri` is now an absolute URI (RFC 9635 3.1) on the origin of `interaction_base_url`.

A GNAP access token response no longer carries `"key": true` (RFC 9635 3.2.1: `key` is an object or string and appears only for a key other than the presented one; a token bound to the presented key omits it). Clients that read `key` as a flag must read its absence as "bound to the presented key".

The issued GNAP access token now echoes the `label` the client gave its token request (RFC 9635 3.2.1). A rotated token does not yet.

A GNAP server can now issue client instance identifiers (RFC 9635 3.5): `GnapService::with_instance_store(Arc<dyn GnapInstanceStore>)` (`InMemoryInstanceStore` provided) adds an `instance_id` to the grant response of every client whose key proof verified, one id per key, and the AS HTTP grant endpoint accepts that id as `client` (2.3.1), checking the proof against the stored key; an unknown id is `invalid_client`. Off unless the store is set.
