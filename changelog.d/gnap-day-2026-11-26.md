Cancelling a GNAP grant request (DELETE on the continuation URI, RFC 9635 5.4) now also revokes the access tokens issued under that grant.

The object form of GNAP `interact.start` (`{"mode":"redirect"}`, RFC 9635 2.5.1) now reads on the wire; an object with no string `mode` is refused when the request is read. A retried token rotation is not answered with a token already past its lifetime, and a token that carries no key leaves no retry record (RFC 9635 11.33). Gap-doc notes: 11.20 narrowed to the responses that carry token material, 11.33 retry is per process, 11.30 is structural.

The `iss` of a GNAP `iss_sub` subject identifier is now the authorization server identifier (RFC 9635 3.4): `GnapService::with_issuer`, else the interaction base URL; with neither, `iss_sub` is not offered. It was the literal `self`.

The GNAP continuation `uri` is now an absolute URI (RFC 9635 3.1) on the origin of `interaction_base_url`.

A GNAP access token response no longer carries `"key": true` (RFC 9635 3.2.1: `key` is an object or string and appears only for a key other than the presented one; a token bound to the presented key omits it). Clients that read `key` as a flag must read its absence as "bound to the presented key".

The issued GNAP access token now echoes the `label` the client gave its token request (RFC 9635 3.2.1). A rotated token does not yet.

A GNAP server can now issue client instance identifiers (RFC 9635 3.5): `GnapService::with_instance_store(Arc<dyn GnapInstanceStore>)` (`InMemoryInstanceStore` provided) adds an `instance_id` to the grant response of every client whose key proof verified, one id per key, and the AS HTTP grant endpoint accepts that id as `client` (2.3.1), checking the proof against the stored key; an unknown id is `invalid_client`. Off unless the store is set.

`JwkSet::cache_control(overlap_secs)` gives the `Cache-Control` value to serve a JWKS with (KM6): half the key overlap, capped at one hour, `no-cache` under two seconds, so a verifier refetches and sees a new key before the old one is destroyed. Evidence: one test; one mutation (no halving) fails it.

A key ring now signs and verifies with ES384 and RS256 keys as well as ES256 and EdDSA (KM6), and publishes them in the JWKS. Evidence: the existing sign, verify and kid test now covers both; the ring skipped them before (it returned no key for any other `alg`).

`keys::revocation_list(store)` returns every revoked or destroyed key (`RevokedKey`: kid, kind, alg, RFC 7638 thumbprint) as the input for publishing revocation (KM5): a CRL, a feed or an event is the host's to build; the crate does not sign or serve it, and the store records no revocation time. Evidence: one test (keys in all four states); one mutation (dropping Destroyed) fails it.

The GNAP service's client-key and proof refusals now start with `invalid_client:` and its no-policy refusal with `request_denied:`, so the AS layer reads the typed section 3.6 error instead of guessing from the wording (3.6). The proof-required description no longer names a crate entry point to the client. Evidence: one test over every constant; it failed before (none named a code); the 340 gnap tests and the 43 AS HTTP tests pass.

A client that keeps polling a pending grant inside the announced `wait` is no longer refused with `too_fast` forever: each early poll counts toward the same per-transaction cap as a wrong interaction reference (`with_max_bad_attempts`, default 5), and the poll that reaches it is answered `too_many_attempts` (`TOO_MANY_POLLS`) and the grant is deleted (5.2, 3.6, 11.27). Evidence: one test (cap 3: two `too_fast`, then `too_many_attempts`, then the grant is gone; control: cap 0 stays `too_fast` over ten polls); it failed before at the third poll; the 341 gnap tests pass.

The interaction hash (RFC 9635 4.2.3) now hashes the absolute grant URL the client used: the origin of `interaction_base_url` plus `transaction_endpoint`, not the bare path (a client that hashes an absolute URL could not verify before). With no base URL the path is still all there is. Evidence: one test pinning the absolute input; it failed before; the 342 gnap lib tests pass.
