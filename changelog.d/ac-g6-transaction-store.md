GNAP open transactions are kept through a `GnapTransactionStore` (`protocols::gnap_store`; `GnapService::with_transaction_store`), in memory by default, so a durable store lets a transaction survive a restart and be shared by several server processes. The store gives a compare-and-swap on a transaction revision and a single-winner `remove`: of concurrent requests with one continuation token exactly one rotates it, and an approved transaction issues its token once; a store error refuses the request. `GnapTransaction` and `GnapTransactionState` are now public. Evidence: born-red concurrency tests and three mutations (CAS without revision, spend by get, spend without revision check) each fail them.
