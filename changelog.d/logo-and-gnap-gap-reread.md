**Breaking: GNAP `httpsig` and `jwsd` key proofs are verified (E1b), and `GnapProof` gains `http_headers` and `http_body`.** A client key with proof method `httpsig` is now accepted when the request carries an RFC 9421 signature (tag `gnap`, covering `@method`, `@target-uri`, `content-digest`, and `authorization` for a token request) by that key, with a nonce that has not been seen before, at issuance, continuation, modification, deletion, rotation and revocation; the key's JWK is kept on the issued token (`GnapIssuedToken::key_jwk`) so management requests are checked against it. Callers building a `GnapProof` by hand must set the two new fields (`&[]` keeps the old behaviour); the AS HTTP layer fills them from the request and lists `httpsig` in `key_proofs_supported`. `jwsd` is accepted the same way through the `Detached-JWS` header (its signature is remembered, so a replay inside the skew window is refused; both listed in `key_proofs_supported`). `jws` stays refused. Also replaces `auth-framework.png` (a Microsoft Designer image under personal-use-only terms) with a FLUX.1 [schnell] (Apache-2.0) logo, provenance in `PROVENANCE.md`, and re-reads the GNAP GAP status column against the code (E2). `GnapService::with_clock` replaces the system clock every expiry, poll-interval and signature-freshness decision reads, so a test can move time instead of sleeping (G10 prerequisite). Every tracked `.rs` file now starts with `// SPDX-License-Identifier: MIT OR Apache-2.0` (E9); `scripts/add_spdx_headers.py` adds it and `tests/spdx_headers.rs` fails when a file lacks it.
