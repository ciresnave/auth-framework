X25519 key-agreement keys in the key stores (KM2): with the opt-in `key-agreement` feature (on the already declared `x25519-dalek`), `keys::generate` creates `KeyKind::JweEncryption` keys (JWK `alg` `ECDH-ES`, X25519), `LocalKey::agree` computes the shared secret and rejects a wrong-length public key and low-order points, and both stores hold them under `keys::agree` (Active or Retiring and exportable only). Agreement keys are written as `v: 2` records (all other keys stay `v: 1`). Downgrade rule: a build older than this one refuses a key directory that holds an agreement key, and there is no convert tool, so destroy the agreement keys with the newer build before going back; a build without the feature refuses such a directory with an error naming the `key-agreement` feature. Evidence: RFC 7748 vectors, the 11 low-order encodings, PKCS#8 exactness, both stores with reopen, and v1/v2 files in the `keys::` tests.
