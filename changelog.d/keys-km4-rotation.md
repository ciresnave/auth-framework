**`keys::rotate`, `retire_expired`, `due_for_rotation`: rotation with overlap for every key kind in a `KeyStore` (ROADMAP KM4).** `rotate` inserts the new key `Active`, then moves the old one to `Retiring` (it still verifies and stays in the JWKS, but no longer signs); it refuses a key that is not active or a replacement of another kind, and leaves both active rather than none if the second step fails. `retire_expired(now, overlap)` destroys retiring keys whose window has passed; `due_for_rotation(now, max_age)` lists active keys old enough for a scheduled rotation. `KeyInfo` gains `created_at` and `retiring_at` (Unix seconds), persisted by `FileKeyStore` (older records read as 0 / none). Each step is logged. No new dependency.
