P-256 ECDH key-agreement keys in the key stores (KM2): **adds `p256` 0.14 as a new direct, optional dependency** of the `key-agreement` feature (RustCrypto, Apache-2.0 OR MIT, `default-features = false` with only `ecdh`, `pkcs8` and `std`; it was already locked at 0.14.0 through `passkey-crypto`, so `Cargo.lock` gains no package and the default build's dependency tree is unchanged). With `key-agreement`, `LocalKey::generate_p256` creates `KeyKind::JweEncryption` keys on P-256 (JWK `kty` `EC`, `crv` `P-256`, `alg` `ECDH-ES`; ECDH-ES of RFC 7518 section 4.6), `LocalKey::from_pkcs8_der` with that kind now also accepts an RFC 5958 P-256 PKCS#8 (it was refused before; a P-384 or Ed25519 key is still refused), and `LocalKey::agree` on such a key takes the peer's uncompressed SEC1 point (`04 || x || y`, 65 bytes) and returns the x coordinate of the shared point; it refuses every other encoding, the identity, and a point off the curve. The stores, `keys::agree`, rotation, revocation and `publish_jwks` work unchanged, and records stay `v: 2` (the downgrade rule of the X25519 slice applies unchanged: an older build, or one without the feature, refuses a directory holding an agreement key, so destroy them with the newer build first). The admin CLI gains `keys generate --kind jwe-encryption-p256` (`--kind jwe-encryption` stays X25519), and `rotate` and `compromise` keep the key's curve. Separately (KM6, rest): the token manager's key ring now signs and verifies with ES384 and RS256 keys as well as ES256, EdDSA and HMAC, and `export_jwks` publishes them; the ring refuses a token whose algorithm is not the one its key id was issued for (HS256 confusion and another asymmetric algorithm are tested), and an RSA key held as PKCS#8 is unwrapped to the PKCS#1 form `jsonwebtoken` signs with, by a strict DER reader with no new dependency. Evidence: the RFC 5903 section 8.1 vectors (re-derived independently with plain big-integer arithmetic) through `LocalKey` and through both stores and a reopen, refusal tests for every malformed peer, and a compile-time test that every type holding secret bytes zeroizes on drop.
