**`AuthFramework::use_key_store` puts the framework's JWTs on a key store.** After `initialize`, `framework.use_key_store(store, policy, every).await` creates an active HMAC key if the store has none, installs a `KeyRing` over the store in the framework's token manager, and starts the maintenance task (returned as a `JoinHandle`) that rotates keys past `policy.max_key_age`, destroys retired keys after `policy.overlap` and refreshes the ring. Tokens carry the signing key's `kid`; the configured secret no longer signs or verifies, so tokens issued before the switch are refused. Nothing changes for a framework that never calls it. Evidence: three new `auth::key_store` tests, each shown red by mutating bootstrap, reuse and ring installation.
