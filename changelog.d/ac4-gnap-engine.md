**`access_control::gnap::EngineGnapPolicy`: the access-control engine behind GNAP (ROADMAP AC4).** It implements `protocols::gnap::GnapAccessPolicy::grant` by mapping the client key's RFC 7638 thumbprint to a principal in the engine's `PrincipalRegistry` and asking the engine, live and never from the cache, about every requested (action, location) pair; the answer is the allowed subset, empty meaning deny. Fail closed: an unknown, revoked or suspended key gets nothing, a request containing `*` in an action or location is dropped (a `*` is a wildcard only in a rule, never in a client's request), a deny grant removes its location, and a poisoned engine lock denies everything. A request with no locations is checked against the whole scope (`*`) and is covered only by a rule whose object is `*`. Additive: no existing API changes. Evidence: 5 unit tests in `src/access_control/gnap.rs`.
