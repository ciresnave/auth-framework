**The admin `keys` CLI can now handle a compromised key and clean up old ones.** `keys compromise --dir D KID` revokes the key at once (no overlap) and installs a replacement of the same kind and algorithm; `keys destroy --dir D KID` erases the private material of a retiring, revoked or pending key and refuses a live one; `keys retire-expired --dir D --overlap-secs N` destroys every retiring key that has been retiring for at least N seconds and leaves the active ones alone. Like `revoke`, these change the key directory only: a running service holding a loaded key ring distrusts a revoked key at its next refresh (or at once if it revokes through `KeyRing::revoke` / `KeyRing::compromise`). A mistyped `--dir` is refused rather than created. Evidence: five new `admin::cli` tests, three shown red by making `compromise` retire instead of revoke, `destroy` revoke instead of destroy, and `retire-expired` ignore its overlap.
