**Breaking: GNAP request `access_token` takes the RFC 9635 shape (ROADMAP G5, slice 1).** `GnapTransactionRequest.access_token` is now `gnap_wire::GnapAccessTokenRequests` (an object or an array; access rights as an object or a reference string), so `{"access_token":{"access":[...]}}` parses; code that builds or reads that field directly must move to the wire type (`vec_of_rights.into()` builds it; `GnapAccessPolicy::grant`, `GnapAccessRequest` and the builder are unchanged). `GnapService::requested_rights` now enforces RFC 9635 2.1.1/2.1.2 before anything is stored or issued: an empty token, an empty access type, labels inside arrays and any `flags` value (`invalid_flag`, since none is supported) are refused, and so is more than one token per request. Not carried yet (G6): `datatypes`, `identifier`, `privileges` and several tokens per request. The G10 conformance vectors are rewritten to the RFC shape (31 requests, structure-preserving). Evidence: 137 gnap lib tests including the RFC-shape and refusal tests, the one-token rule's removal fails exactly the new refusal test, and clippy `--all-targets` is clean.
