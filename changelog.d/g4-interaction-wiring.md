**Breaking: `GnapTransaction` gains a public `user_code` field and `GnapInteractionFinish` a public `hash_method` field, and a GNAP request whose `interact.finish` is malformed or whose `push` target is not public https is now refused at transaction open.** The grant service reads `interact.start` and `finish` through `gnap_interaction` (G4 slice 1): an unknown `finish.method`, a bad callback URI, or a `push` to a loopback, private, link-local or metadata address (RFC 9635 section 11.34) is an error and stores nothing; a `finish.hash_method` other than `sha-256` is refused with an error naming it (the service computes sha-256 only, so it must not be ignored); a `user_code` start is answered with a generated code kept on the transaction. Delivering the push and re-checking its target after name resolution are not built yet. Evidence: four service-level tests, each failing when its call site is removed.
