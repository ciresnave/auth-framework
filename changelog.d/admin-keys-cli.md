**The admin CLI can now manage a key directory.** `auth-framework-admin cli keys` has `list`, `generate`, `rotate`, `revoke` and `jwks` over an encrypted `FileKeyStore` (`--dir`): `generate --kind jws-signing|mtls|dpop|http-sig|gnap-client|hmac|aead [--alg es256|es384|eddsa|rs256] [--kid ID]` makes an active key, `rotate KID` replaces it with a new one of the same kind and algorithm and leaves the old one retiring, `revoke KID` withdraws a key at once, `list --format table|json` prints id, purpose, algorithm, state and times and never key material, and `jwks` prints the JWK Set of the live public keys. The directory's encryption key comes from `AUTH_STORAGE_ENCRYPTION_KEY` / `AUTH_STORAGE_ENCRYPTION_KEYS_FILE`, never the command line, and a typo'd `--dir` is refused instead of creating an empty store (only `generate` creates one). Needs the `cli` feature. Revoking from the CLI changes the directory only: a running service that holds a loaded key ring distrusts the key at its next refresh. Evidence: six new `admin::cli` tests, three shown red by skipping the revoke, the missing-directory check and the algorithm carry-over.
