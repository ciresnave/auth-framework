**`TokenManager` can sign and verify through a key store.** `TokenManager::with_keyring(KeyRing)` makes the manager sign with the newest active HMAC key of a `KeyStore` and verify by the `kid` in the JWT header against every active or retiring key (the rotation overlap); a revoked, destroyed or pending key, an unknown or missing `kid` and a stale snapshot are refused, and the secret the manager was built with is not used as a fallback. A `KeyRing` is a snapshot refreshed with `refresh(&store)` after a change or on a timer by `spawn_maintenance`, which rotates a key past `max_key_age` and destroys a retired one after `overlap` (`maintain_once` does one pass). Nothing changes for a manager built without a ring. Evidence: eight new `tokens::keyring` tests, each shown red by a mutation of the state filter, the staleness bound, the signing choice and the header.
