**Breaking: `RsError` gains an `InvalidAccess` variant, and is now `#[non_exhaustive]`; a downstream `match` on it must add an arm for `InvalidAccess` (it is answered as `invalid_access`) and a wildcard arm.** GNAP resource set registration (RFC 9767 section 3.4): `gnap_rs::GnapResourceServerApi::with_registry` offers a registration endpoint decided by a deployer-supplied `ResourceRegistry` (the RS authenticates with the same `ResourceServerAuthenticator` as for introspection); `access` and `resource_server` are required, `token_formats_supported` is checked against the formats the AS issues, and the answer carries `resource_reference`, `instance_id` when the registry gives one and the `introspection_endpoint`, with `Cache-Control: no-store`. The discovery document lists `resource_registration_endpoint` only when registration is offered. `gnap_http::GnapRsHttp` routes it (`registration_path`), and the axum and actix adapters register the route when it exists. `RsError` is now `#[non_exhaustive]`, so a later variant is not breaking again. The language-neutral suite `tests/conformance/gnap/rs-vectors.json` is version 2 with 14 registration vectors.
