**The admin `keys` CLI can now print a certificate or a certificate request for a stored key.** `keys self-signed --dir D KID --cn NAME [--dns NAME]... [--days N]` prints a self-signed X.509 certificate (PEM, 365 days by default) and `keys csr --dir D KID --cn NAME [--dns NAME]...` a PKCS#10 request to send to a CA (see `keys::certificate_request_from_csr` for the server side, which verifies its proof of possession). Both work for an active asymmetric key (ES256, ES384, EdDSA, RS256) in a store that can export it and refuse a retiring, revoked or destroyed key, a symmetric key, a missing key, a zero validity and a mistyped `--dir`. The output is public information; the private key stays in the directory. Evidence: four new `admin::cli` tests that parse the printed certificate and request (subject, names, validity, self-signature, the stored key's public point, proof of possession), three shown red by ignoring `--days`, skipping the active-key check and dropping the request's DNS names.
