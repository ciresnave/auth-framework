**Breaking (storage): sessions are now sealed at rest by `EncryptedStorage` (ADR-011, slice 3 of 4).** `store_session`, `get_session`, `delete_session`, `list_user_sessions`, `count_active_sessions` and the bulk session methods keep each session as one encrypted record in the backend's key-value space, indexed by keyed hashes, so no session id, user id, address or user agent appears in a stored key or value. Key names beginning `sess:` and `sessuser:` are reserved, as the token prefixes already were. A session stored before this release is read through while `allow_plaintext_reads` is true (sealed, old row deleted); with it false it is unreachable by lookup but `delete_session` still removes it. The exact `count_active_sessions` is now a key scan on a sealed store, so the login path no longer calls it: `auth_modular::SessionManager::count_active_sessions_cached` reuses a per-process count for up to 30 seconds (this process's own logins raise it at once), which `create_session_limited` uses for the 100 000-session cap and `AuthFramework::delete_session` for the monitoring gauge; the cap can therefore be exceeded by about login rate x 30 s x processes, and the gauge can lag after a logout. Statistics keep the exact count. Sessions held by a consumer-supplied `session::SessionManager<S>` are not covered.
