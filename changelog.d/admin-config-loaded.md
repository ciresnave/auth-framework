The admin binary now reads the configuration it is given: `--config` and `--env-prefix` were accepted but ignored, so every run used the built-in defaults with an empty in-memory store while printing that the file was loaded. A `--config` path that is missing or unreadable is now an error; with no `--config` the binary reads `config/auth-framework.toml` if it exists and otherwise says on stderr that it is using the built-in defaults. `auth_framework::admin::load_settings` is the loader.
