**Breaking: GNAP polling enforces `wait`, and the client can modify or cancel a pending grant (ROADMAP G5, RFC 9635 sections 5.2-5.4); two fields renamed (SEC-012, #463).** `GnapService` gains `with_poll_wait_secs(n)` (default 5, 0 = off), `modify_transaction_with_proof` (PATCH: a pending transaction only, no `client` or `interact`) and `delete_transaction_with_proof` (DELETE: the client cancels its grant). A poll before `wait` has elapsed is refused with `TOO_FAST`, keeps the continuation token and restarts the clock; `GnapTransaction` gains `last_poll_at`, so literals of it must add the field, and callers that poll faster than 5 seconds must now wait or set `with_poll_wait_secs(0)`. Renamed with their wire names kept: `GnapTransactionRequest.access_token` is now `access_token_request` and `ServiceProviderConfig.change_password` is now `change_password_flag`; `AcmeChallenge.token` carries its `// sec012: public` marker. The HTTP routes for 429 `too_fast`, PATCH and DELETE are the surface lane's. Evidence: 271 lib tests match `gnap` with the CI feature set (6 new), `gnap_conformance` and `gnap_rs_conformance` pass, two tests pin the renamed fields' wire names, and CI clippy and `cargo +stable fmt --check` are clean. Also: **the admin binary now reads the configuration it is given (#442, M12).** `--config` and `--env-prefix` were accepted but ignored, so every run used the built-in defaults with an empty in-memory store while printing that the file was loaded; a `--config` path that is missing or unreadable is now an error, and with no `--config` the binary reads `config/auth-framework.toml` if it exists and otherwise says on stderr that it uses the built-in defaults (`auth_framework::admin::load_settings`; cherry-picked from e3d43ccf). Evidence: two binary tests fail on the old code (it printed "Configuration loaded" for a file that does not exist) and pass with the fix.
