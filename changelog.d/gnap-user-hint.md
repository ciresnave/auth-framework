**Breaking: `GnapTransactionRequest` gains `user: Option<GnapUserRef>` (RFC 9635 2.4).** The service now reads the `user` a client names: its shape is checked (a malformed one is `invalid_request`, nothing stored), and its `sub_ids` join those under `subject` as a hint (11.13), so subject information is released only when the user the AS saw approve matches one of them. A user reference or assertions name nobody the AS can match and change nothing. Migration: struct literals of `GnapTransactionRequest` add `user: None`; or use `GnapTransactionRequest::builder().user(..)`. Evidence: `section_2_4_user_hint_is_checked_and_narrows_subject_release` in `gnap.rs`.
