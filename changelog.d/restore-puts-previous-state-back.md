A restore that fails part-way no longer leaves the store wiped: before it resets anything it keeps the current state in memory, and if the reset or the writes fail it puts that state back and says so in the error (`Restore failed and the previous state was put back: ...`); if putting it back fails too, the error says the store may be incomplete. Dry runs and snapshots that fail validation or decoding are unchanged (they never touch the store).
