**Breaking: the GNAP continuation URI the server issues is now `{transaction_endpoint}/continue/{transaction id}` (was `{transaction_endpoint}/continue`), in the first response and in every polling response; a client that built the continue URI itself instead of using the `continue.uri` it was given must use the issued one.** A request that carries only `Authorization: GNAP <continue token>` and a DPoP proof could not be routed to its transaction, because transactions are keyed by id and the old URI carried none (RFC 9635 section 5 lets the AS choose the URI). The conformance vector `tx-continue-offered` now asserts the new prefix through a new `starts_with` op; the test `continue_uri_names_the_transaction` follows the issued URI and token alone through two polls.
