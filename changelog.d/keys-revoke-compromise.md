**Key stores can now revoke a key at once and replace a compromised one.** `keys::revoke(store, kid)` moves a `Pending`, `Active` or `Retiring` key to `Revoked` with no overlap window: it signs and verifies nothing and leaves the JWKS immediately. `keys::compromise(store, current, next)` revokes the old key first and then installs `next` (same kind) as `Active`, so a compromised key is never trusted while its replacement is created; if installing `next` fails the old key stays revoked and the error says so. Both refuse a key that is already revoked or destroyed. Routine replacement is still `rotate`. Evidence: six new `keys::rotation` tests, four shown red by making both functions retire instead of revoke.
